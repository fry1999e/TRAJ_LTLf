# 项目架构

## 入口与配置

`main.py` 定位项目根目录并加载 `src/cli.py`。`config/manual.json` 提供输入、输出和审核默认值；命令行参数优先。人工模式要求 `manual / human / api / manual / manual`，交互式审核需要终端。

## 核心流程

1. 读取自然语言需求及公开 AP 定义。
2. 由用户审核表面切分，主模型检查普通语言读法。
3. 提取来源明确的 AP 候选，经人工确认后建立 AP 身份上下文，再构建并由模型检查语义 IR，通过用户对通俗轨迹情景的判断选择解释。
4. 形成受限骨架、类型化时序孔及有限轨迹证据。
5. 冻结已审核证据，补全候选公式并执行一致性检查。
6. 输出公式及审核状态；不完整或冲突项目保留待审状态。

`agents/` 负责生成任务，`llm/` 提供 API 传输，`rag/` 提供通用知识检索，`contracts/` 提供来源与数据契约。语义、编译、审核和断点模块位于 `src/`。

## 数据边界

`data/` 按 `input / examples / output` 组织。`input/*.xlsx` 只包含需求原文和 ID，`input/manifest.json` 记录文件摘要及 ID 对应关系。`input/sources/` 保留原始来源文件供溯源，不作为默认在线输入。根目录的 `LTLf_Evaluation_Dataset.xlsx` 按数据集分为三个工作表，合并完整需求与离线参考式；`data/manifest.json` 记录工作簿、来源文件及完整评估内容的摘要。默认知识库仍只读取 `examples/knowledge_base/` 中的通用文档。

`dataset_workbook.py` 提供文本单元格校验和 XLSX 生成；`requirement_loader.load_requirement_records` 按扩展名分派 XLSX 或 Markdown 输入。XLSX 输入只接受一个工作表及原文、ID 两列，拒绝 Excel 计算公式、重复 ID 和额外参考列。离线导出工具只从评估表选择前两列，参考公式的变化不影响生成的输入文件。文档属性和 ZIP 条目时间固定，锁定 openpyxl 版本后可逐字节重建输入表。

默认在线流程读取指定需求文件和通用知识库，不读取参考式。人工只审核切分、AP 和轨迹是否符合原文。主生成模型负责普通读法和语义结构检查，并将用户的通俗选择整理为内部标签、置信度和理由。轨迹判断仍以用户选择为准；模型改变该判断时，程序拒绝响应，不自动批准冲突标签。

`nonexpert_review.py` 保存原始人工作答、模型生成的技术字段及其来源。内部标签使用 `human` 标记决定来源，`metadata_source=model_assistant` 和模型标识区分解释的生成来源；语义结构检查使用 `model_assistant` 来源，不冒充人工审核或独立模型审核员。单条、批量、IR 分支判别和补充轨迹使用相同的通俗审核入口。

AP 准备采用通用的“来源校验—定向修复—人工确认”闭环。`ap_proposal_validation.py` 批量定位引用、名称与跨 AP 重叠错误，区分同一谓词复用、并列谓词拆分以及不同谓词共享主语这几类修复需求；不冲突候选保持原有含义和引用。只对名称及引用集合完全相同的重复声明本地去重，其他修复由模型根据原文重新提出，仍需后端校验和人工确认。受限的符号谓词提取是该闭环中的快速路径，不改变一般自然语言处理及批准门禁。

`human_review_session.py` 为同一来源与 AP 含义提供跨阶段的判断复用和累计 5 个不同情景的上限。实际时间表的摘要用于合并等价问题，检查目标用于选择每组首批最多 3 个代表情景，长度用于同等覆盖下的排序。原始判断与模型技术字段分别保存；复用时重新绑定当前 query ID 和证据用途，保留原始作答来源。候选解释已唯一确定或关键目标已覆盖时提前停止，必要时补充到累计上限。未询问的问题没有标签，覆盖门禁继续检查真实证据；单条和批量在停止提问后进入现有公式回退，断点保存未完成检查及停止原因。

达到上限仍不能完成检查时，通俗审核入口保留原始判断，将模型技术字段标为 `deferred_for_candidate_fallback`，直接返回已有合格注释。未生成注释的原始判断通过预算记录单独传递；`candidate_delivery.py` 验证原文、AP 上下文、AP 含义、时间表摘要与原始选项一致性，仅将确定判断用于临时候选排序。它们不进入已审核轨迹、覆盖或学习门禁，不虚构模型置信度及理由。

普通人工切分由本地规则提供初稿，人工确认与无损校验不变。`llm/overlap_client.py` 以后台请求将 AP 提取与切分/读法检查重叠，将来源图提案与 AP 人工输入重叠；只在完整请求及参数一致时消费预取 JSON。提案仍在正式阶段用已确认 AP 上下文解码、检查和编译，审核来源不因预取而改变。后台线程不继承终端输入上下文；前台仍负责等待符号。物理请求观测、引导样例及非 API 客户端保持原来的传输路径。

`pre_ir_review.complete_plain_reading_review` 统一主模型辅助与保留的 Judge 后端的读法确认、选项决定和状态写回，`plain_reading` 统一审核状态、单一 IR、候选 IR 及最终输出门禁。单条和批量路由依据同一就绪状态，选项映射也不按审核来源切换规则。审核者标识和证据来源保留在记录中；来源不同不改变同等材料的放行标准。命令行仍限定人工模式，未恢复旧的独立审核命令。

未决读法通过受约束的选项映射进入现有候选 IR。模型只可对应已有选项，后端检查来源重叠、一一对应及分支完整性；人类轨迹证据唯一选出分支后，读法标记为 `human_trace` 来源的已决记录，重绑 IR 并同步断点。无法构建完整候选时保留未批准状态，另行生成可输出的公式候选。

`source_graph_resolution.py` 处理语义图报告的 `semantic_axis`。主模型只能将差异对应到已存在的后端语义轴；后端重新构建并验证所有选项组合，完整后交给轨迹审核。原始差异、对应依据和模型标识保留在来源图和语义记录中。无法对应或不完整的图通过有类型异常进入共用的生成恢复路径，具体原因保留，不会因输出候选而获得语义批准。

`requirement_reading_contract.py` 统一读法与语义图的任务约束，防止凭空增加截止时间或软建议含义。读法检测后继续由模型提交选项决定和理由，原始检测证据转存历史；真实未决读法仍走候选门禁。覆盖台账使用 AP 上下文中的全部来源片段，并依据无界 eventuality 的后端契约排除“未指定固定截止时间”这类非缺口描述，保留真实的边界及范围差异。

AP 提取读取完整原文，后端定位引用范围，允许一个谓词跨越多个阅读片段。模型提案始终保持未审核状态；只有用户明确确认后才形成已审核 AP 清单。批量断点保存该清单，续跑复用相同的来源绑定。来源图 v4 使用 `ap_name` 选择已有 AP 身份，由后端填入来源片段；兼容旧的坐标提案，范围错误最多修复一次，修复不能改变其他语义结构。

## 运行状态

`candidate_delivery.py` 将已声明的算子范围构造成具体 IR，并在正常选择没有输出时执行候选回退。所有回退公式均经 IR 编译和一致性评分，从现有合法范围中选出一条；编译选择与语义批准分别记录。单条、批量、终端和精简文件使用同一输出候选，审批与学习写回门禁继续保留。

首次生成和收到修改意见后的重新生成均优先经 `IRProposalRouter` 提交公式无关的来源语义图，IR 节点、时序候选和规范作用域由后端构造。修改意见随图提案传入，不能覆盖原文或已审核 AP。重新生成未通过 IR 校验或 AP 图绑定失败时，单条和批量入口重新验证已有候选的原文、AP 上下文与审核父记录，保留仍有效的候选供回退，并写入 `invalid_revision_rolled_back` 记录。时序提示中的见证范围 `strict_suffix` 与 IR 的 `scope` 字段分开，严格未来含义由节点及拓扑表达。

`semantic_review_view.py` 构造紧凑的模型检查上下文：完整图和候选按引用去重，保留原文、AP 证据、节点参数、歧义、读法及语义决议，排除旧版 trigger/response 摘要和重复审核历史。语义图的批准条件仍由原有门禁判断。基于原文、AP 上下文、图含义、候选分支和读法的指纹在单条及批量闭环中检测重复拒绝，写入 `SEMANTIC_REVISION_NO_PROGRESS` 后保留未批准候选。传输层按生成参数复用客户端连接，输出 schema 单次绑定；正式请求结果不跨轮缓存，人工选择与模型响应仍分别留档。

`formula_generation_fallback.py` 在没有已有 IR 时使用主生成模型补生成一条公式，最多三次语法与名称修复。后端将解析树降为绑定已审核 AP 的可执行 IR，再执行编译及一致性检查；该 IR 标记为 `working_interpretation_v1`，不声称已证明与原文等价。完整提案及图失败原因保存在独立审核记录，IR 本身仍不包含完整公式字段。输出使用共用的单公式回退；原文语义批准、人工标签与学习写回条件保持独立。批量保存候选断点，恢复时核对原文、AP 上下文和审核父记录，不重问已完成的 AP 审核。用户取消审核或输入来源失效不会被此路径覆盖。

每个运行目录保存输出、人工记录、断点和补充轨迹。不同输入或模型使用不同目录。运行状态由本地运行生成，持久记忆默认关闭。
