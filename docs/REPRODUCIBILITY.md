# 使用与复现

## 环境配置

使用 Python 3.13，按根目录 README 创建虚拟环境，安装 `requirements.lock.txt`，复制并填写 `.env`。固定生成模型名称、服务地址、温度和 token 配置。不同模型服务版本及用户判断可能产生不同输出。

## 输入检查

```powershell
python -B scripts/prepare_inputs.py --verify
python -B scripts/check_reproducibility.py --check-dependencies
```

输入检查会核验 XLSX 输入、完整评估表及原始文件的摘要，并逐字比较输入需求与评估表中的原文和 ID。离线导出工具只选择评估表中的 `Natural Language / Requirement ID` 两列；参考公式列不影响导出结果，也不进入在线生成上下文。

数据布局见 [data/README.md](../data/README.md)。在线需求位于 `data/input/*.xlsx`，原始来源文件位于 `data/input/sources/`。完整需求与参考式合并在 `data/LTLf_Evaluation_Dataset.xlsx`，按 `Requirement ID` 对应，仅供离线比较。整理目录不会改变需求 ID、原文、参考式或已存在的运行结果。

需要重建缺失的三份数据集输入表时执行 `python -B scripts/prepare_inputs.py --write`。该命令拒绝覆盖已有不同内容。自定义需求请另建 XLSX 文件，首行为 `Natural Language / Requirement ID`，每行一条需求和唯一文本 ID；也支持 Markdown 文件中的稳定 `## REQ-编号` 标题和 fenced text 原文。

## 交互审核

```powershell
python -B main.py --review manual --experiment-mode human --llm api --segmentation-review manual --plain-reading-review manual
```

人工只需确认表面切分、AP 含义和轨迹是否符合原始需求。普通语言读法和语义结构由主生成模型检查。命令及 `--plain-reading-review manual` 参数保持兼容，流程不再要求用户填写语义结构评审表。

该命令的读法确认与 IR 门禁采用保留的 `judge` 审核规则，两种审核来源调用同一实现。无歧义必须有明确确认；选择读法必须引用当前选项；拒绝全部歧义后必须重新确认无歧义。未决歧义通过完整的有类型映射后可进入候选 IR，形成可编译的候选后允许回退输出，原始审批状态保持独立。缺失输入或失效来源仍需修正，不能编造公式。来源记录区分主模型辅助与独立审核，不作为放行条件；发布入口仍仅支持人工命令。

AP 阶段输入 `a` 确认的是原子命题及其原文绑定，后续仍需通过语义检查和轨迹审核。模型新检测出的读法也必须继续判断原文支持性，不能仅因被模型提出就保持未决。输入按待满足的时序需求处理；不能仅因出现 `should` 凭空引入“只是建议”的读法，原文明示可选或非约束含义时则必须保留。`eventually` 本身不要求固定或可测量的截止时间，缺少这样的时间值不构成能力缺口；真实的时间界限、作用范围及当前/严格以后差异仍需审核。模型的读法选择、理由与先前检测证据分别保存在审核记录中。

轨迹逐条展示原始需求、AP 含义和时间表格：行是从 `t0` 开始的时刻，列是 AP，单元格使用 `true / false`。同一轮列顺序固定，未发生过的 AP 和全部为 `false` 的时刻仍显示，最后一行之后情景结束。表格直接由实际轨迹生成；审核记录保存展示格式与列顺序。用户输入 `y`（符合）、`n`（不符合）、`u`（无法判断）或 `i`（情景不可能）。空输入不会批准。主模型负责整理内部标签、置信度和理由，用户无需掌握 SAT 等术语。模型不能改变用户的判断；不确定或不可能的情景不会被当作确定证据。IR 解释的差异也使用相同的轨迹交互处理。

`review_records/nonexpert_trace_review_*.json` 分别保存原始选择和模型生成内容；标签判断来源为人工，技术解释来源为模型。模型响应失败或试图改写判断时保留原始选择并停止当前处理，不要求用户补填专业字段。语义及普通读法检查记录为 `model_assistant`，不会标记为人工批准。

情景交互区分“需求含义确认”和“关键情景核对”，同一原文及 AP 上下文只显示一次审核说明。每组首批最多 3 个不同情景，按检查目标的覆盖增益和表格长度选择；判断已唯一确定解释或覆盖关键目标时提前停止，否则少量补充，跨阶段累计最多 5 个不同情景。相同时间表只问一次，原始判断可以绑定多个检查目标，但不会变成多次独立人工作答。

`review_records/human_trace_session_*.json` 保存以原文、需求 ID、AP 上下文指纹及 AP 含义绑定的判断。上下文相同时跨阶段和续跑复用，改变原文或 AP 含义后重新审核。`nonexpert_trace_review_*.json` 同时保存 `review_context`、`query_groups`、`reused_choices`、`deferred_query_ids` 和 `review_budget`，可核对实际询问数量、复用来源及未审核项目。技术字段生成失败后重试时，已保存的原始回答不必重新填写；`u / i` 始终保留其不确定或不可行情景含义。

停止提问不会补造缺失标签或放宽语义批准规则。完整覆盖未完成时，记录 `HUMAN_REVIEW_BUDGET_REACHED`（达到上限）或 `HUMAN_REVIEW_KEY_SCENARIOS_COMPLETE`（关键情景已完成），保留未批准状态并回退输出一条公式。单条与批量遵循相同规则；批量断点保留已有证据及停止原因，续跑直接复用。需要重新作答时可显式使用 `--fresh` 开始新的运行。

达到 5 个情景上限且仍有未审核项目、也尚未唯一确定解释时，`metadata_status` 记为 `deferred_for_candidate_fallback`，跳过新的模型说明请求。原始人工作答仍逐条保存，`review_budget.fallback_evidence` 记录来源及 AP 上下文。仅确定的 `y / n` 可用于候选回退排序，`u / i` 保持未决；未生成的置信度和理由留空，不创建已通过技术审核的轨迹。回退记录用 `raw_human_trace_count` 区分这些判断；它们不补齐覆盖、不批准候选、不写入学习记忆。原本有资格继续完整审核或唯一确定解释的情景仍由模型整理技术字段。

模型保留多种读法时，程序将读法选项对应到后端已有的有类型语义候选，支持中文等普通语言描述；映射不能添加 IR 操作或省略选项。用户的轨迹判断唯一确定解释后，读法记录随之更新为已决，并同步更新 IR 来源及批量断点，无需另填语义审核表。已有可编译候选但未能唯一判断时执行候选回退。尚未形成可执行候选的读法问题写入 `review_records/plain_reading_pending_*.json`，保留具体生成原因。

无需额外参数，默认 `--progress auto` 会在交互终端等待期间仅显示转动标识，包括重试及响应格式修复。返回响应或发生错误后动画停止，人工输入时不会刷新等待行。此行为覆盖单条需求和文件批量输入。非交互输出使用静态 `...` 标识；`--progress plain` 强制静态标识，`--progress off` 关闭进度显示。

同一 API 客户端复用连接，按生成参数区分连接实例；响应 schema 每次独立绑定，服务不支持格式约束时仍使用原有兼容和本地校验。语义检查使用 `faithful_ir_review_v1` 视图：保留全部节点、AP 原文依据、候选分支、未决选项和当前读法，重复图只传一次，省略审核历史、传输记录及可能失真的旧版 trigger/response 摘要。完整工件仍写入审核记录。模型检查允许候选尚未选定，候选选择继续由人工轨迹和后端门禁处理。

单条与批量均比较被拒绝候选的实际含义；仅节点编号或旧摘要变化不算新候选。重新生成仍返回相同含义时，记录 `SEMANTIC_REVISION_NO_PROGRESS`，停止重复模型检查，保留未批准候选继续后续处理；候选的结构、分支假设、原文、AP 上下文或读法变化后仍重新检查。此优化不会改写人工标签、批准候选或读取离线参考公式。

普通人工切分使用本地无损候选，保留逐字校验及人工确认；专门配置的引导样例流程维持原有生成规则。普通 API 客户端使用 `llm/overlap_client.py` 在人工切分及读法检查期间预取一次 AP 提案，在人工 AP 审核期间预取一次确有需要的来源语义图提案。预取只请求 JSON，不建立批准或冻结记录；正式阶段按系统提示、完整请求和参数精确匹配，消费后即删除，不跨轮缓存结果。AP 提示中的身份审核记录编号不传给图生成模型；模型只引用名称和原文片段，Python 在确认后绑定真实身份。修改原文、AP 证据或未决读法导致不匹配时不复用。预取失败在真正使用该请求时按原有规则报告；取消审核不等待预取完成。需要物理请求记账的观测运行禁用后台预取。

普通 NL 缺少 AP 定义时，程序先检查是否为可完整识别的符号谓词片段，例如 `p holds`、`p and q hold` 或 `prop_12 occurs`。仅在剩余词汇全为已识别连接和时序框架、每次符号出现均有谓词依据时，本地提出独立的符号 AP；来源记录为 `source_symbol_predicates_v1`。候选经过相同原文绑定校验，保持未批准，仍须人工确认；不会自动确定并列或时序关系。该路径也跳过不再需要的 AP 模型预取。文章中的不定冠词、其他领域谓词、否定或无法识别的时间限定会使该窄规则退出，继续模型提取。

其他自然语言由主生成模型提出候选并校验原文引用，每轮最多尝试两次。提示明确要求并列谓词拆分及重复谓词复用，修复反馈要求保留全部含义并消除重叠，不能仅更换复合 AP 名称。两次均失败时，交互模式显示具体原因及未通过的候选，可输入 `r` 重新生成，或输入 `e` 修改，再输入 `a` 明确确认；无有效候选时输入 `a` 不会放行。正常生成后同样显示 AP 名称及原文依据供审核。直接修改一个 AP 的原文依据，其余 AP 保持不变：

```text
e grant_occurs grant | occur
```

名称后的内容是原文依据（`evidence_texts`），一个片段无需引号，多个片段用 `|` 分隔；也支持 JSON 列表，例如 `e grant_occurs ["grant","occur"]`。输入名称必须与当前显示的 `canonical_name` 一致，找不到名称时不会添加或修改其他 AP。单独输入 `e`，或输入 `e grant_occurs`，会依次提示选择现有 AP、新名称、原文依据；新名称或依据处回车表示保留该字段。可连续修改多个 AP，最后统一输入 `a` 确认。无效修改不会覆盖当前有效候选。旧的完整 `e {"aps":[...]}` 形式仍兼容，但它替换整个候选列表。

修改后仍需输入 `a` 才批准。`c` 或未完成审核会停止当前项目的 IR 生成。引用必须来自原文，时序词和连接词不能单独充当 AP。阅读切分只影响展示，AP 证据可以跨多个片段。建议按完整谓词或子句切分，例如 `e Whenever request occurs, ⟦CUT⟧grant should eventually occur.`。

AP 引用应保留事件或状态本身；例如 `grant` 可作为发生事件的依据，整个 `grant should eventually occur` 会把时序词包进 AP。生成阶段会检查这类引用并请求模型重新提取，随后仍由用户确认 AP。

一般自然语言的校验由 `ap_proposal_validation.py` 一次收集全部引用错误、名称冲突、时序词混入和跨 AP 重叠，并在 `ap_repair_feedback.issues` 中保存问题代码、涉及候选、具体引用及原文坐标。第二次请求使用定向修复提示，要求拆分独立谓词、复用相同谓词、为同一实体的不同事件补全区分性引用；不冲突的候选列入 `preserve_candidates`，其名称和引用集合不能被删除或改写。修复后的完整列表重新经过相同校验，失败时仍保留具体原因，不能放行错误来源。

名称及引用集合相同的重复条目可本地去重，无需增加模型请求；不同名称或不同引用不会被静默视为同一谓词。词组中的 `and/or` 本身不会导致拆分，例如实体名称中的并列词仍可保留。适用范围包括一般领域短语、中文需求、重复主语、重复事件及非连续证据。成功后 `ap_review_*.json` 的 `proposal_generation` 保存原提案、各次校验和修复反馈、去重结果及最终有效候选，最终批准来源仍为人工。

英文引用按完整单词或标识符匹配。例如 `occur` 仅绑定原文中独立的 `occur`，不会绑定 `occurs` 内部的子串；同一需求中存在 `occurs` 不会导致合法的独立 `occur` 被拒绝。中文引用无需空格边界。原文不存在的引用、跨 AP 的证据冲突及时序整句仍不能批准。

未修正的提取失败会保留具体校验原因；单条入口写入 `review_records/ap_pending_*.json`，记录两次失败的候选与原因，便于排查。恢复后批准的记录包含修正来源，程序不会自动确认模型提案。

AP 确认后，语义图可能报告 `semantic_axis`，表示仍有待处理的解释差异。主模型先检查该差异能否完整对应后端已有的有类型候选，例如 eventuality 的“当前或以后”与“严格以后”；程序验证候选覆盖全部选项组合后，继续人工轨迹审核。该对应不会批准任何分支，也不能增加节点或忽略能力缺口。对应依据及模型标识保存到语义记录的 `source_axis_debt_resolutions`，批量断点续跑保留这些记录。

语义覆盖检查使用已绑定 AP 的全部原文片段，而不局限于模型选择展示的一个片段。若模型省略根部 `whenever` / `every time` 明确要求的全程范围，后端按原文补齐该范围；普通 `if` 不会据此被扩展。以上处理均不代替后续人工轨迹判断。

无法完整表达的差异保留为未批准依据，生成流程自动恢复：已有合法候选时保留候选；尚无候选时，主生成模型依据原文、已确认 AP 及普通读法补生成一条公式，Python 校验语法、AP 名称和编译结果。语义图、具体差异和补生成依据保存在 `formula_generation_fallback` 阶段的审核记录中。该候选不声称已通过完整语义审核。审核者仍只需审核切分、AP 和轨迹，无需补填专业语义字段。

人工确认记录写入运行目录的 `review_records/ap_review_*.json`，批量运行同时保存 AP 清单断点。新语义图使用 `ap_name` 引用已确认名称，原文范围由后端填入；旧的坐标形式继续兼容。坐标错误可修复一次，修复不能改变布尔或时序结构；仍失败时自动保留或补生成公式候选，不再要求重复确认 AP。

完整数据输入通过 `--requirements-file data/input/A72.xlsx` 等指定。为不同数据、模型和独立运行选择不同的 `--run-dir`。相同命令、输入和运行目录可继续批量断点。

结果、人工记录和断点应一起保存。改变输入或模型时使用新目录。`--fresh` 会重置所选运行；持久 RAG 默认关闭，防止其他运行中的决定混入当前输入。

## 文件式批量审核

默认逐项交互。需要先准备人工切分文件时，显式使用 `--pre-ir-mode deferred` 和 `--human-segmentation-file`；读法检查由主生成模型处理。

人工切分文件包含以下头部：

```text
format: traj-ltlf-human-segmentation
schema_version: 1
```

每条需求使用与输入一致的 ID，在 `source_text:start/end` 和 `human_marked_text:start/end` 注释之间各放一个 fenced text 段落。前者逐字填写原文；后者由用户在原文中插入 `|`，移除切分符后必须还原原文。缺失或不匹配的项目会阻断。

程序读取人工切分后自动整理读法检查，并在后续阶段请求 AP 和轨迹判断。已有断点中未完成的普通读法检查也会交给主生成模型处理；模型无法确定的真实歧义保留给候选 IR 和轨迹判别，不直接授予最终公式批准。

## 结果判断

每条需求最终输出一条公式。正常选择未得到唯一结果时，使用已有候选回退；`F / XF` 等声明过的算子读法先构造成具体候选，避免在判别前停止。两轮轨迹判别仍不唯一、模型语义复核达到上限或覆盖不足时，回退按已有人工轨迹一致性、评分与稳定顺序选取一条通过编译校验的公式。人工的未知回答不会变成布尔证据。没有可编译候选属于生成或输入错误，不以占位公式掩盖。

AP 已确认但首次语义图生成失败时，自动补生成公式候选，不依赖先前存在 IR。补生成最多三次，失败响应及具体校验错误会反馈给主生成模型；程序不接受未审核 AP 或用常量代替需求。批量断点保存补生成候选与原始记录，来源和 AP 上下文一致时续跑直接复用。旧断点中的 AP 语义图绑定失败会重新进入自动恢复流程。API 不可用、三次补生成均不合法、输入来源失效或用户取消审核时仍报告实际原因。

模型提出修改意见后，重新生成仍使用同一来源语义图路径，由后端构造 IR，避免直接生成 `eventually_strict / strict_suffix` 等冲突字段。新提案未通过校验时，已有候选经来源、AP 上下文及审核父记录复核后保留，用于候选回退；失败原因保存为 `invalid_revision_rolled_back` 审核记录。该过程无需审核者补填专业语义表单，也不会将回退选择标为人工批准。

`final_candidates.txt` 保存单条输出及回退选择方式；单条入口将来源、赋值和评分依据保存到 `review_records/formula_fallback_REQ-001.json`，批量结果也保留回退记录。回退公式不自动获得语义批准，不写入已批准记忆；内部审批、来源和证据记录仍保留。无需添加命令行参数，也不启用模型审核员。

查看 `outputs/final_candidates.txt` 和 `outputs/manifest.json`，区分最终候选、待审、降级及阻断。有限轨迹检查只说明公式在已检查证据上的行为，不自动构成全语言等价证明。
